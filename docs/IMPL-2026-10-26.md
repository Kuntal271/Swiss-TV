# Implementation round — new functionalities (2026-10-26, evening)

Written by the takeover agent after the owner asked for "more functionalities" while the TV
was in family use. Constraints that bound every idea here: third-party app (no system
permissions), D-pad only, the owner's father is the main viewer, no Google anything,
design source `docs/design/project/*.dc.html` (deviations below are owner-requested).

## In scope now (recommended set — owner may strike any item)

### F1. Comfort text size (Settings → Home → "Text size")
**Why:** the design's smallest type (18–22 px on a 1080p canvas) is small for older eyes.
**What:** a setting cycling 100% → 115% → 130%; every text on every screen scales with it
(layout, tiles and art keep their geometry — only font sizes grow).
**Plan:** `LauncherSettings.textScale` appended as the LAST field (protobuf field order rule).
The design module's text primitives (`T`, `TDraw`, `Label`, `TabText`, `KeyHintText`,
`CrossfadeText`) multiply the style's font size by `LocalTypeScale` provided in DesignCanvas
from settings. Pure helper `scaled(type, scale)` is unit-tested. Hero/keep maxLines already
tolerate 2-line titles; verified visually later on TV.
**Files:** `core/design/Type.kt`, `core/design/DesignCanvas.kt`, text primitives, `domain/Models.kt`
(settings field), `data/Stores.kt` (if schema needs it), `feature/settings` row, unit test.
**Effort:** M. **Risk:** long labels wrap — maxLines already set everywhere; spots to watch:
Header nav labels, PosterCard title box (fixed 2-line box: unchanged geometry, bigger glyphs).

### F2. Weather on Home (next to the clock)
**Why:** Google TV showed weather; this launcher shows none. One glance at the top-left.
**What:** `24° · Mostly clear` under the date, muted, same baseline row. No key, no tap.
**Plan:** `platform/tv/Weather.kt` — open-meteo current temperature + weather code
(no API key): `GET /v1/forecast?latitude=..&longitude=..&current=temperature_2m,weather_code`.
City from a small bundled preset list (Mumbai default; the owner can say another city and we
add it — no runtime geo, no permission). Refresh: cold start + every 30 min while the
launcher lives; cache last good value on disk (survives restarts, shown stale with no age
mark). Pure parser `WeatherParse` unit-tested against a saved response. Nothing shows when
offline/failed. Weather codes map to a small icon glyph + short text.
**Files:** new `platform/tv/Weather.kt`, `data/DataGraph.kt` wiring + StateFlow, Home clock
row, `data/src/test` parser test. **Effort:** S–M. **Risk:** open-meteo blocked? Jio DNS
blocks some hosts — tmdb needed api.tmdb.org; if api.open-meteo.com is blocked, fall back to
wttr.in text or drop silently (log only).

### F3. "Now playing" chip on Home (info only, not focusable)
**Why:** YouTube keeps playing after Home; nothing on Home says what.
**What:** a muted one-line chip bottom-right above the key hints:
`▸ Now playing · YouTube — <title>`; fades with the entrance; disappears when nothing plays.
Purely informational — **no focus item** (the focus graph, key routing and hint bar stay
untouched); to open the app the user still uses its tile.
**Plan:** `MediaSessionWatcher` publishes `nowPlaying: StateFlow<NowPlaying?>`
(pkg, title) from its existing emit path (main looper, change-driven + 30 s tick).
`HomeScreen` collects it and draws the chip when non-null and Home is on top; the chip's
text truncates to one line, title max 40 chars. Apps playing WITHOUT a title (Netflix)
show just the app name. Suppressed while that same app's card is focused? No — always
shown while playing; it is one line, muted.
**Files:** `platform/tv/MediaSessions.kt` (+ flow), `feature/home/HomeScreen.kt`, wiring.
**Effort:** S. **Risk:** none structural; titles can be long (truncated).

### F4. Letter jump in All apps (hold UP at the top row)
**Why:** the grid will only get longer; scrolling row by row to "W" is slow for everyone.
**What:** UP at the very first row (the geometric graph would stop) opens a slim letter bar
overlay (letters that actually have apps); UP/DOWN moves the letter, OK jumps the grid to
that letter's first app, BACK/any side key closes it. Grid scroll is the existing eased
`scrollTo`; the ring stays on the target tile.
**Plan:** `AllAppsScreen`: `grid.onEdge` already fires for blocked edges — a top-row UP edge
opens the overlay (own `rememberFocusScreen` like the move-mode `mover`, so no key reaches
the grid while it is up). Jump = index of the first app whose upper-cased label starts with
the letter. Hidden apps excluded (they are already out of the list).
**Files:** `feature/apps/AllAppsScreen.kt` (+ small overlay composable). **Effort:** M.
**Risk:** low; overlay shares the footer band like the Hold-OK menu.

## Parked — need the owner's decision before building (do NOT guess)
These were asked on 26 Oct evening and not answered yet; they stay parked until the owner
picks. Feasibility findings from probing the TV (read-only) are noted.

1. **Power-off icon (header top-right).** A normal app cannot press the power key
   (framework handles it before apps; REQUEST_SHUTDOWN has no resolvable activity on this
   firmware). Feasible paths: (a) device-admin `lockNow()` granted once by setup.sh
   (standby like the remote's power key), (b) a minimal accessibility service +
   GLOBAL_ACTION_LOCK_SCREEN (the a11y fallback is deliberately OFF for the 10 ms/frame
   cost — a no-event-types service should be near-free but needs measuring), (c) open
   TCL's energy-saving page (no new power). Recommend (a) + a confirm dialog ("Power off
   the TV?"), because standby also clears Continue watching.
2. **Reset icon (header top-right).** Options: restart the launcher app itself (feasible,
   safe), clear Continue watching (feasible), reset settings to defaults (feasible), reboot
   the TV (NOT feasible from an app on this firmware — adb only). Recommend
   "restart launcher".
3. Both icons sit next to Settings on a TV the father also uses → at least one of
   confirm-dialog / hold-OK is strongly recommended for the power icon.
